# Contributing

Thanks for your interest in Consult. This file covers what you need to know
before opening a PR.

## Skills and the core

Read [`AGENTS.md`](AGENTS.md) first. It sets the test every line must pass,
the wording rules, and the shape and size caps that
`scripts/validate_skills.py` enforces. Edit the sources under
`agents/.agents/` only; `plugin/` is generated by `make plugin`.

## Branching and commits

- Branch per change: `feature/`, `fix/`, or `refactor/`.
- Imperative-mood commit subjects under 72 characters that explain why, not
  what. No AI-attribution trailers (`Co-Authored-By`, `Generated-by`).

## Local checks

Run before opening a PR:

```sh
make check   # validator, plugin drift, ruff, mypy, pytest
make eval    # eval verifier sync and rule-check tests; runs no models
```

They need `python3` 3.12 or newer, `uv`, and Node 22 for `make eval`. CI
runs the same targets. To run `make check` before every commit:

```sh
git config core.hooksPath .githooks
```

`make eval-fast` and `make eval-triggers` run real agent trials and bill the
subscription they run under. Run them only when a change needs that
evidence.

## The marketing site

`site/` is static HTML, CSS, and JavaScript, published to GitHub Pages when
it changes on `main`. Preview it with live reload:

```sh
python3 scripts/serve_site.py
```

`site/skills/index.html` is generated from `core.md` and each skill's
frontmatter. Run `python3 scripts/build_site_skills.py` after changing
either; the tests fail while the page is stale. The evidence page's figures
come from `eval/results/`, and the tests check every one.

## Pull requests

- One logical change per PR. Rebase onto the current `main` before opening.
- Reference any related issue and explain the engineering motivation.
- A new or changed rule needs eval evidence that it changes behavior, as
  `AGENTS.md` describes.

## Reporting bugs

Open an issue with: a short title, the agent host in use, the skill
involved, the prompt or scenario that reproduces the behavior, and the
observed and expected outcome.

## Security

Security disclosures go through the channel described in
[`SECURITY.md`](SECURITY.md), not public issues.
